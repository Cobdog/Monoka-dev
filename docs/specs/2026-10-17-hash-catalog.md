## 1. The problem, and the ruling

The engine registry lists NAMES. `GET /models/{kind}` answers a flat list of
subpath strings — no sizes, no digests; the loader enums in `/object_info`
answer the same names again ([DOC] instanceInventory.ts; devdocs §4). Every
identity claim the app makes today is therefore name-shaped: the inference
ladders match basename regexes + filename quant tokens
([DOC] modelSelection.ts — "the registry reports no byte sizes"), the VAE
decoder-class and TE dimension-class guards are name heuristics "with known
limits" ([DOC] modelOverrides.ts), and the stack report's `isCanonical` is a
basename string compare ([DOC] h3Stack.ts).

The walkthrough put real numbers on what that costs:

- The models home served **four diffusion checkpoints one name-ladder can
  confuse** — official FL2VA, official Ref2VA, a Viggle-Animate build (an
  H3-ref2VA finetune; drbaph's int8-convrot 47.03 GB / pruned-int8 21.03 GB
  quants [DOC] assumption-register P2-1) and a pre-merged hybrid
  (smhfacct b25-49 int8, already sha-pinned in the fetch catalog [DOC]
  fetchCatalog `smhfacct-hybrid-b25-49`). Renamed or re-cut, none of these
  is distinguishable by name — and the merged/community shape is
  name-invisible BY DESIGN ([DOC] modelOverrides: "that is this layer's
  reason to exist").
- **45 VAE files including ~30 near-duplicate
  `minimax_h3_video_vae_fp16__setCMBalias2`-style variants** ([DOC] r3
  P1-9) — an alias soup the pickers enumerate verbatim and no surface can
  collapse.
- Same bytes, different names, is not hypothetical: the taeh3 decoder ships
  as TWO different artifacts under one naming convention — 9,791,388 bytes
  (Kijai) vs 39,458,084 bytes (simsim9 pack) — recorded as a DATED
  CORRECTION in the fetch catalog after the names collided ([DOC]
  fetchCatalog `taeh3-preview-decoder`).

The verdict-truth symptom (review Theme 3.1): "H3 engine ready" pills beside
"the H3 stack is incomplete", the missing thing never NAMED, and a fetch
remediation offered for files that are present under a name the ladder
misses.

**The maintainer's ruling (2026-10-15), verbatim:**

> "SHA matching… We can easily catalog hashes for all variants of models we
> support, different quants, etc. And creating a primed hash list of the
> models we know we support. This would not gate new models being added…
> but it will make it easy to see if it really does not exist first before
> we say we have to download it."

This spec is that ruling made buildable: a shipped catalog of sha256
identities crawled from the publishers without downloading a single weight,
consumed as **detection evidence only — identity by hash, names as fallback,
never a gate**.

## 2. The catalog artifact

A **generated, versioned, append-only JSON file shipped in the repo**:

- `server/hashCatalog.json` — the data (generated by the crawl, committed;
  the server is detection's only consumer — the client receives verdicts
  through the stack/inventory payloads, never the raw catalog).
- `server/hashCatalog.ts` — the typed loader: rows plus the two indexes
  (sha256 → row; basename alias → row ids).
- **The transport is pinned here — `ModelFile.identity?`** (audit H-I2,
  the wizard-facing interface, in the blessed text): `ModelFile` gains an
  optional `identity: { verdict: 'hash-confirmed' | 'name-suspected' |
  'unknown'; family?, artifact?, variant?, quant?, … }`, populated
  server-side through `identifyModel` wherever a verdict is computable
  and ABSENT where it isn't (remote engine, unconfigured root, hash in
  flight). The field rides the payloads that already carry
  `ModelFile[]` — the inventory scan response and the session bootstrap —
  so the client's `h3StackReport` (computed over the session store) reads
  verdicts with no second fetch and no new route; a hash upgrade
  re-publishes the file through the same field (the inventory settle,
  §6). No payload ever carries the raw catalog rows.

**Row shape** (one row per distinct sha):

```jsonc
{
  "sha256": "a629cfea8d89a071b140c6e1935dc9a23e72de6badc18975a2bb9e6d1423d76d",
  "sizeBytes": 20970379632,
  "kind": "diffusion_models",
  "identity": { "family": "minimax-h3", "artifact": "hybrid", "variant": "smhfacct-b25-49", "quant": "int8", "dtype": "int8" },
  "source": { "repo": "smhfacct/Minimax-H3-fl2va-ref2va-hybrid-models", "revision": "a36feb17…", "path": "minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors" },
  "aliases": ["minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors"],
  "addedAt": "2026-10-17"
}
```

- **Identity fields per the card's AC:** family, artifact (fl2va / ref2va /
  hybrid / viggle / video-vae / audio-vae / t1-image-vae / te-32b / turbo-8
  / …), variant, quant, dtype, kind, source repo + revision + path, size.
- **Name-shape aliases are the SECONDARY key**: every publisher filename the
  crawl saw for that sha (the same bytes legitimately live under several
  repos/names — Kijai's taeh3 under two names today). Hand-appended aliases
  land as dated additions, never edits.
- **Append-only, like the registry goldens**: rows are never modified or
  deleted; corrections append (`retiredAt`, the fetch catalog's `removedAt`
  precedent). Enforcement joins the existing append-gate class on MAIN
  merges (the `scripts/check-registry-append.cjs` pattern — [DOC] its
  header states the contract verbatim). Regeneration is deterministic:
  unchanged crawl manifest → byte-identical file (canonical sort).
- **Envelope:** `{ version, generatedAt, crawl: [{ repo, revision, fetchedAt }], rows: [...] }` — the provenance block IS the record of every source
  and date.

The modularity contract: the catalog is DATA consumed through one seam
(§4). Delete the file and the loader and detection degrades to today's
name-shape behavior — nothing else moves.

## 3. The crawl (how the file is generated)

- **Mechanism [DOC]:** HF's tree APIs expose per-file LFS sha256 OIDs
  without downloading weights — `GET /api/models/{repo}/tree/{rev}?recursive=true`
  (datasets via `/api/datasets/...`), each LFS entry carrying
  `lfs.oid` (sha256) + `lfs.size`. This is the exact mechanism that
  verified every fetch-catalog pin, dated 2026-09-14/15/20/26 in that
  file's header — the crawl industrializes an established practice.
- **Known limit [DOC]:** license-gated repos mask the LFS oid for anonymous
  reads (the w4a8 VAE case). The crawler sends no credentials — the
  fetcher's no-credentials rule extends to it — so gated artifacts land as
  honest gap entries (row present, sha marked unrecoverable-anonymously,
  the w4a8 VT-reference workaround applied only where already
  established). Never a guessed hash.
- **Source set** (the crawl manifest — data in the generator, greppable,
  extended by append):
  1. every `source.kind === 'hf'` repo in FETCH_CATALOG — weights,
     preprocessors, datasets (the `removedAt` LTX history rows excluded);
  2. the supported families' full variant/quant enumerations beyond fetch
     rows: the official H3 FL2VA/Ref2VA quants (bf16, int8 convrot, pruned
     int8 — the central home already holds fl2va int8 convrot,
     sha `7ad4c73e…`, and the 32B TE int8 convrot, sha `bc2ced0f…` [DOC]
     MANIFEST); the 32B TE cuts (int8 convrot / nvfp4 awq / bf16) plus the
     4B/8B companions (class evidence for the dim-class guard); the video
     VAE fp16/fp32 cuts and audio VAEs (the MANIFEST's distinct shas); the
     Mamad8 T=1 decoder; both taeh3 decoders; Viggle-Animate (official
     bf16 shards + the drbaph quants + r64/full-rank LoRAs); the smhfacct
     hybrid presets; the lightx2v/larryvrh/drbaph turbo-LoRA lines; VDN
     stages; the Fun-Control union; the Qwen Image 2.1 trio's quants; the
     Krea 2 edit lines.
  The official-release repo ids are the crawl's FIRST verification act —
  the manifest asserts them, the crawl proves or corrects them (dated
  addendum if wrong). [SPEC]
- **Dated re-crawl convention:** every crawl stamps per-repo revision +
  date in the envelope; a new family or quant lands with its rows in the
  same commit (the licenses registry's verify-on-trigger pattern, [DOC]
  policy §6). The generator (`scripts/crawl-hash-catalog.mjs`, node,
  zero deps) is agent/maintainer-run — never app-run, never CI (CI stays
  networkless).
- **Licensing/provenance:** the shipped file is factual metadata — sha256,
  size, repo path, revision. Facts about public artifacts, not weights,
  not license text; the same class of fact the fetch catalog's pins
  already ship. One `docs/licenses/registry.md` row for the generator +
  generated file lands in the same commit as the file (the lockstep
  audit's never-forget). No community-license text is embedded; nothing
  gated is fetched. [SPEC — the row's wording is a blessing input]

## 4. Detection integration (the one seam)

**Doctrine first [DOC]:** h3Stack.ts's own module head records the bug this
section must not repeat — it "once carried its own expectation table… a
SECOND source of truth beside the inference ladders", and present models
read MISSING until the parallel table died. The catalog therefore enters
through ONE derivation, and every surface reads that:

```ts
// server/modelIdentity.ts [SPEC]
identifyModel(file: { name: string; kind: ModelKind }, sha256?: string)
  → { verdict: 'hash-confirmed' | 'name-suspected' | 'unknown'; identity?: CatalogIdentity }
```

- **`hash-confirmed`** — the app read the bytes locally and the sha matches
  a row: the row's identity IS the file's identity, named in human words
  ("Ref2VA · pruned int8 convrot — official MiniMax release").
- **`name-suspected`** — the ladder or alias index matched, but there is no
  byte evidence (remote engine, unconfigured root, not yet hashed). The
  label says so: "identified by name only — unconfirmed".
- **`unknown`** — no match. Fully usable; nothing changes for it (§5).

**Read-reach rules.** The app hash-confirms only files it can READ through
the configured per-kind model roots — the same roots fetches land in, the
same contract the animation lane already ships ("the studio runs beside the
engine on the same box… an unconfigured root or an unreadable enumerated
name is a NAMED refusal — never a name-only pass", [DOC]
server/animation/models.ts; devdocs addendum 2026-10-09: ComfyUI serves
**no** digest surface for weights — `/experiment/models` carries
mtime+size, never a hash — so reading the files is the only honest digest
source, verified at v0.39.0). Remote engines and unconfigured roots cap at
`name-suspected`, honestly labeled. The app never downloads bytes to hash.

**Who designates the roots (audit H-I3).** Hash-confirmed's read-reach is
exactly as wide as the configured per-kind model roots — and on a fresh
clone `modelRoot` defaults to the studio home, a directory the engine
does not read: hashing there proves nothing about the engine's real
weights, and the engine's real dirs are unconfigured. The designation
moment is the wizard rework's Models step (its destination designations,
D7 there — audit W-C1; this set's CT-1): "where should fetched weights
land so your engine sees them" IS the roots designation, and it is what
turns this spec's headline value on for the product-bar journey. Until
it lands, everything renders name-suspected, honestly labeled — AC-4's
cap is the product-bar journey's default state, not an edge case.

**Where the verdict lands** ([SPEC] — each consumes the one seam; and the
first is a behavior change in resolution, honestly named, not a
consume-only shuffle: the ladder gains a top rung — audit H-M1):

- **Resolution (the false-missing killer):** a registry file whose hash
  confirms an artifact becomes a resolution candidate for that artifact's
  slot EVEN WHEN ITS NAME MATCHES NOTHING — identity is a new top rung
  above the name ladder. (Duplicate-bytes tie-break, audit H-M2: when two
  registry files hash-confirm to the same artifact — the alias soup
  guarantees it — the slot resolves to the best basename match against
  the row's aliases, ties breaking in stable registry order; the rest
  render as the *other candidates* of the picked/ambiguous presentation.)
  A renamed official Ref2VA resolves the reference
  lane; the stack verdict never says "incomplete — download Ref2VA" about
  bytes it is serving. The merged slot stays the one deliberate exception:
  it never auto-infers today ("name-invisible BY DESIGN") and v1 keeps that
  — a hash-confirmed hybrid is NAMED, with a one-click "use as merged pick"
  affordance, not silently loaded.
- **h3Stack rows:** `isCanonical` upgrades from basename compare to
  sha-equality against the slot's canonical artifact rows; each row gains
  `identity` + verdict; the Theme 3.1 disposition ("one verdict computed
  once, hash-confirmed identities named, human sentences") becomes
  mechanically true.
- **modelOverrides class guards:** where hash evidence exists, the VAE
  decoder class and TE dimension class come from the identity row — the
  name heuristics remain the fallback for name-suspected files, their
  documented limits unchanged.
- **The wizard's Models step (3p14abm):** consumes the same verdicts
  through the server payload. This spec owns the interface; presentation is
  the wizard spec's.
- **The fetch surface:** a "download X" remediation may appear only when X
  is truly absent — hash-confirmed presence under ANY name removes the
  suggestion (the ruling's "see if it really does not exist first").

## 5. The non-gating guarantee — testable invariants

The ruling's own words are the contract: "This would not gate new models
being added." As invariants:

- **N1 — no new blocks (monotone improvement), split per audit H-I1.** For
  any inventory, the set of accepted submissions and legal picks with the
  primed catalog is a SUPERSET of the set with a null catalog — nothing
  legal today becomes illegal; no file or pick gains a new refusal. Fetch
  *suggestions* are the deliberate exception, and one-directional: they
  may only be REMOVED (and only when the artifact is hash-confirmed
  present under some name — §4), never added, never mandated. For engine
  files ABSENT from the catalog, behavior is bit-identical to today — the
  unrecognized model is never blocked, never flagged, never second-class.
- **N2 — no forced downloads.** No code path triggers, mandates, or nags a
  fetch because a catalog row exists but the file is absent. Fetching stays
  exactly what it is: explicit, consented, opt-in. A catalog row may only
  REMOVE a fetch suggestion (artifact hash-confirmed present), never add an
  obligation.
- **Test shape [SPEC]:** a vitest suite runs the resolution/validate seams
  against the same fake inventory twice — null catalog vs a primed fixture
  carrying the §7 quartet + soup — asserting: every null-catalog acceptance
  survives; every null-catalog missing-model refusal that the primed catalog
  resolves flips ONLY via the hash-confirmed path; uncataloged files'
  outcomes are identical; zero new refusal strings. A fake-engine e2e walks
  an uncataloged engine file through wizard → submit unchanged.

## 6. Local-hashing mechanics

Built ON the shipped seam, not beside it [DOC]: `server/animation/models.ts`
already streams sha256 (`digestWeightFile` — never whole-file buffered),
caches by `(absPath, mtimeNs:size)` stat key in an LRU, and refuses
honestly when a root is unconfigured or a file unreadable. The catalog work
**hoists that seam into a shared server module** (`server/modelIdentity.ts`)
that the animation lane then delegates to — one hasher, one cache, no
second digest path. [SPEC]

- **What gets hashed:** only registry-listed files a pending verdict needs
  — stack-verdict computation, an override pick's class check, an explicit
  identify action. No boot-time sweep; no inventory-wide walk; hashing is
  lazy and memoized.
- **Progressive reveal — the vocabulary is defined HERE** (audit H-I4,
  with the wizard's W-I4; the catalog owns it, the surfaces render it):
  hashing is lazy with no background pass (B5), so the first stack
  verdict on a big stack renders MINUTES before the digests exist. The
  interim state is part of the verdict vocabulary every consuming surface
  uses: a file whose hash is in flight renders **"verifying bytes —
  identified by name for now"** (name-suspected, verifying marker); when
  the digest lands, the verdict upgrades in place — `hash-confirmed`,
  identity named — through the same `ModelFile.identity` field (§2; the
  inventory settle re-publishes the file). No surface invents its own
  interim word; the wizard's Models step (3p14abm §2.2) renders this one.
- **Size pre-filter (the cheap gate):** stat first; if `sizeBytes` matches
  no catalog row, a hash cannot hit — skip and report unknown (unless the
  user explicitly asked to identify that file). This is discriminating
  even on lookalikes: the T=1 image VAE (5,207,808,784 bytes) and the
  musubi video VAE fp16 (5,207,808,496) differ by 304 bytes — size alone
  separates them before any bytes are read [DOC] MANIFEST. The 34 GB DiT
  hashes once, streaming, minutes-class; the alias-VAE soup is sub-second
  per file after the first — and a cold-cache first hash is still one
  read per file, so ~30 aliases on a cold NAS collapse over
  seconds-to-minutes, not instantly (the walkthrough prose promises no
  instant soup collapse — audit H-M3).
- **Off the main loop:** digesting gigabytes is exactly A-7's
  no-long-synchronous-work class — hashing runs worker-threaded/queued, the
  animation seam's pattern generalized. [DOC] remediation-plan §6 A-7.
- **Cache persistence:** v1 ships the persistent sidecar (app-home,
  `path + statKey → sha`) — a restart must not re-hash 34 GB; strict
  stat-key invalidation, so replaced-under-same-name weights re-hash (the
  animation lane's own requirement, [DOC] devdocs addendum).

## 7. Acceptance criteria

| # | Criterion |
|---|---|
| AC-1 | **The quartet resolves by hash.** A fixture engine serving the four diffusion checkpoints (official FL2VA, official Ref2VA, Viggle-Animate, smhfacct hybrid) under RENAMED names — no family token in the basename, the name-invisible case — with readable roots: each verdict is `hash-confirmed` and NAMES the identity; the FL2VA/Ref2VA lanes resolve (no false "stack incomplete"); the hybrid is named with the merged-pick affordance, not silently loaded; no fetch suggestion appears for any present file. |
| AC-2 | **The VAE soup collapses.** A fixture with the alias set (distinct shas + byte-identical aliases, sampled from the ~30-variant walkthrough shape): identical shas group under one named identity; decoder-class verdicts come from identity rows, not name markers; a T=1-NAMED file hashing to the video VAE is named as the video VAE — the name's lie corrected by bytes. |
| AC-3 | **Non-gating holds.** The N1/N2 suite passes (null vs primed catalog over the same inventory); an uncataloged engine file flows through wizard → submit bit-identically to today. |
| AC-4 | **Remote honesty.** Against an engine whose files the app cannot read: every identity verdict is `name-suspected`, labeled unconfirmed; nothing anywhere claims `hash-confirmed` without bytes read. |
| AC-5 | **The crawl round-trips.** Regenerating with an unchanged manifest yields a byte-identical file; append-only holds across MAIN merges; the envelope carries per-repo revisions + dates; the licenses registry row landed in the same commit. |
| AC-6 | **One derivation.** h3Stack, the override guards, and the wizard payload all consume `identifyModel` — no surface re-encodes a sha→name table (grep-able invariant, the module-head doctrine); and the only client transport is `ModelFile.identity` (§2) — no payload ships raw catalog rows (audit H-I2's wire-shape clause). |

## 8. Blessing decision points

| # | Decision | Recommendation |
|---|---|---|
| B1 | **Shipped file vs fetchable index.** | SHIP the generated file — offline-first, no new runtime network dependency, exactly the ruling's "primed list". A fetchable index adds a phoning-home surface for zero detection value. |
| B2 | **Crawl cadence.** | Event-driven — every new family/quant commit carries its rows — plus the quarterly registry sweep absorbing a dated re-crawl. Never CI (networkless). |
| B3 | **Do the app's own records adopt the identity rows?** | Fetch INSTALL RECORDS gain the catalog id (post-fetch self-verification against the row); the animation snapshot's `ModelContentIdentity` gains an optional catalog reference. The central-home MANIFEST stays machine-local (may cite ids; never app-generated). |
| B4 | **Gated-repo policy.** | Honest gap entries; the crawler never sends credentials (the fetcher's rule extended). |
| B5 | **Persistent hash cache + background pass.** | Persistent sidecar YES (v1 — restarts must not re-hash 34 GB); a quiet background hasher NO — on-demand only; a background pass can ride idle diagnostics later if hashing ever shows up as latency. |
| B6 | **v1 source-set scope.** | Fetch-catalog repos + the full H3/Viggle/hybrid/VAE/TE/turbo enumerations now (crawl-cheap — metadata only); the community-turbo long tail (the walkthrough's 10 combobox names) included in v1. |

## 9. What this spec deliberately does NOT do

Not a gate (§5 is the whole point). Not tamper-evidence — sha256 here is
identity, not an integrity police. Not engine-side — no ComfyUI changes.
Not the pickers' filtering fix (r3 P1-9 — other families' checkpoints in
the FL2VA picker) — **owner: jxb34l0** (standing IA; stated once there —
audit CT-4 resolved this spec's old "is the wizard round's" claim). Not
licensing enforcement — the obligations-not-policing stance governs. Not a
second truth table — §4's one-seam rule, on the module-head doctrine's own
evidence.
